## 2026-09-06 drift check

The weekly cron flipped this skill to `status: provisional` on two failures ([`2026-09-06-maplibre-pmtiles-patterns.csv`](2026-09-06-maplibre-pmtiles-patterns.csv)):

- **Test 3** — the rubric failed. The answer presented a bare `ArrayBuffer`, `Blob` or `Response` as the v4 return value; the rubric (tightened in #85) requires the `{data}` object. The skill never stated the v4 return shape anywhere — it only showed `maplibregl.addProtocol('pmtiles', protocol.tile)` — so the earlier pass was the model's own knowledge, not the skill's.
- **Test 6** — the `not-icontains: "tileset:"` tripwire fired: the answer offered "the `url:` property (or `tileset:` in newer MapLibre versions)" and repeated `url:` (or `tileset:`) three more times. No such source property exists. The rubric failed on the same invention; its reason also claimed the answer named the inspection command `pmtiles info`, but that string appears nowhere in the output — a judge misread, and that tripwire passed.

Both gaps are now taught: the skill states the `addProtocol` contract (v3 `(params, callback)` gone in GL JS 4.0.0, a v4 handler being `async (params, abortController)` resolving to `{data, cacheControl?, expires?}`, ❌ v3 handler beside ✅ v4 one, and `pmtiles.Protocol().tile` already `v3compat`-wrapped so PMTiles users need no code change), a ❌ line naming `url` and `tiles` as a source's only tile-location properties, with no `tileset` in the style spec, a ❌ line closing the go-pmtiles subcommand list, and the `addProtocol` API page in the References.

The 2026-09-07 re-run passes 6/6 and `status: verified` is restored. Two earlier attempts that day are not the recorded run. The first failed test 3 on the `map.addProtocol` tripwire: the draft said the handler belongs on the module "and never on a map instance", and the model wrote the forbidden string back while correcting it — inventing a per-map v3 registry on the way. That sentence was reworded to state the module registration positively. The second passed 6/6, but against text whose ❌ example still claimed a v3 handler never resolves on v4+; review corrected the failure mode (the handler is handed an `AbortController`, so `callback(...)` throws, and the synchronously returned `{cancel}` carries no `data`, so the tile arrives as an empty buffer), gave the `v3compat` shim its `pmtiles` ≥ 3.0.0 floor, and narrowed the `tileset` claim to the spec as checked. The recorded CSV is the run against that final text.

## What the rubrics guard against

Three tests once passed at baseline on invented code because their rubrics scored the concept, not the code, and test 4 passed with the skill on the model's own story because its rubric asked for a fact the skill did not state. Each now names the real API beside a tripwire for the invented one, and the tripwires are doing work the rubric text alone did not (tests 3 and 4 fail at baseline on their tripwire alone; the judge passed both rubrics):

- **Test 1** — `protocol.tile` and the `Protocol` class from `pmtiles`; tripwire `not-icontains: pmtiles.get(`. Verified against [`js/src/adapters.ts`](https://github.com/protomaps/PMTiles/blob/main/js/src/adapters.ts).
- **Test 3** — the v4 handler shape (`async (params, abortController)` resolving to `{data}`) on the module-level `maplibregl.addProtocol`; tripwire `not-icontains: map.addProtocol`. Verified against [`src/source/protocol_crud.ts`](https://github.com/maplibre/maplibre-gl-js/blob/main/src/source/protocol_crud.ts), whose own doc example returns `{data: buffer}`, and [`src/util/config.ts`](https://github.com/maplibre/maplibre-gl-js/blob/main/src/util/config.ts) for the `AddProtocolAction` signature. The skill must state the return shape, not assume it: a rubric that names a fact the skill omits is graded against the model's own knowledge, which is what drifted on 2026-09-06.
- **Test 4** — `pmtiles show --metadata` and the `vector_layers` array, with `icontains: pmtiles verify`. Verified against [`show.go`](https://github.com/protomaps/go-pmtiles/blob/main/pmtiles/show.go), which prints a metadata value that is not a string as `<object, use --metadata to view full JSON metadata>`, and the [PMTiles spec's JSON Metadata section](https://github.com/protomaps/PMTiles/blob/main/spec/v3/spec.md#5-json-metadata). The baseline answers invent `pmtiles info`, `pmtiles validate` and `pmtiles list`.
- **Test 6** — the answer must say that with the archive's own `maxzoom` supplied MapLibre **overzooms** the deepest stored tiles, and must not patch the archive's metadata; tripwires `not-icontains` for `pmtiles inspect`, `set-metadata`, `pmtiles info`, and `tileset:`. go-pmtiles has none of those subcommands (`main.go` declares `show`, `tile`, `cluster`, `edit`, `extract`, `merge`, `convert`, `verify`, `serve`, `upload`, `version`), and the style spec has no `tileset` key — `source_vector` and `source_raster` in [`src/reference/v8.json`](https://github.com/maplibre/maplibre-style-spec/blob/main/src/reference/v8.json) locate tiles with `url` or `tiles` only.
